# ODC 负责范围

部署新版本前先在目标数据库执行本目录 migration.sql。此迁移只新增负责范围表和索引，不写入账号、组织、角色或业务人员数据。不要使用 schema push 代替迁移。

关系为工作区 → 现有成员 → 现有中心 → 负责部门。部门来自中心下的服务单位，保存时校验归属；无记录表示尚未配置，department_id 为 NULL 表示明确负责全部部门。删除中心挂靠、成员或部门时相应关系级联清理。

系统设置的 ODC 负责范围仅允许工作区 owner/admin 维护。Excel/TSV 以邮箱匹配现有 ODC 成员，以中心名及中心内部门名匹配组织；重名或缺失会阻止整批导入。导入先预览，提交时重新校验，事务内只新增缺失关系。不会覆盖原有序列、服务单位限制，不更新账号角色或 TG。单条维护明确替换该成员在该中心的部门配置；清空部门仅清除推荐配置，保留中心挂靠。

AI 审批选择 ODC 时，以候选人当前岗位的中心、部门匹配：对应部门优先，其次全中心，其他部门及未配置人员仍可选择。原有中心、岗位序列、服务单位、角色权限等资格条件不变。部门推荐不直接授予候选人查看权限；仍须业务审核通过并明确分配。
