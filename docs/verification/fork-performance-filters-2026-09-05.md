# 浏览器生命周期修复与 ReUI Filters 迁移

参照 `/Users/wen/dev/github/ai-interview` 的性能提交 `c6831574`、`c8c60522`，以及筛选提交 `cba6f38b`、`95436674`、`1d8d3751`、`0511c000`，在当前 fork 中适配。未合并上游分支、重命名工作区或修改数据库结构。

## 性能

- 水印使用稳定文本依赖及专属 DOM 容器；页面卸载后异步 create 完成时再次清理。
- 页面卸载时销毁 OverlayScrollbars 实例，并停止批量上传状态轮询。
- 复选框使用常驻视觉标记，避免 Presence 为每个取消勾选项触发退出提交。修复前取消 100 项产生 101 次 React 提交，修复后的回归限制为不超过 3 次。
- 这些测试覆盖具体资源生命周期和渲染开销；未执行数小时的生产环境持续运行测试，不能据此排除其他卡顿原因。

## 筛选

源码来源为 [ReUI Base Filters](https://reui.io/docs/components/base/filters)，复用上游仓库的 Filters/Cascader 本地调整，不覆盖项目的其他 UI primitives。注册表 dry-run 因远端连接失败未完成，因此使用已存在的上游源码。

共同页面采用独立文本字段及 `textFilters` JSON 标量参数；服务端按资源白名单验证，字段之间 AND，文本按字面包含匹配。数据库查询保持原有租户及权限谓词，列表与总数复用条件。公司、学校查询直接读取本项目已有结构化简历字段；本 fork 没有上游的搜索索引和数据库搜索函数，因此不依赖那些函数，也没有宣称具备上游索引性能。

招聘页继续保留现有姓名、邮箱、电话、ID、ODC、组织和岗位筛选参数，补充公司/学校等原子条件。成员过滤仍保留匹配成员的上级行及 TG 字段；私有池上传人范围不被清空操作移除。历史导入、预登记、数据导出及队列等本项目独有的关键词接口仍显式启用原有搜索协议。

超过两个字段采用条件标签；空条件及输入草稿不请求，文本 Enter/失焦提交，单选即时提交，多选切换即时提交。日期边界和技能 ALL 语义保留。清空原子更新页码和查询条件，保留排序、页面上下文、固定范围和展示字段。`arc:list-filter-selection:v1` 仅保存字段键，不保存条件值或候选人数据。URL 支持 TanStack Router 已解码的 JSON 对象与标量文本形式。
