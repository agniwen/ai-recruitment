# 部门/中心（来源）组织层级

招聘基础设置新增“部门/中心（来源）”，关系为：部门/中心（来源） → 用人组织 → 部门。
它是招聘组织层级，独立于简历已有的 Boss、智联、内推等渠道字段。

## 设置流程

1. 在“招聘基础设置 → 部门/中心（来源）”中新建来源。
2. 编辑用人组织，选择其所属部门/中心（来源）；一个用人组织最多属于一个来源。
3. 在部门/中心（来源）列表中“管理 ODC”或“设置 ODC”。序列、服务单位留空表示不限。

ODC 按岗位直接关联的部门/中心（来源）访问岗位；简历可见性继续按岗位序列和服务单位筛选。调整组织归属、移除分配或取消成员角色的 ODC 标记后，后续请求按最新配置判定。

部门/中心（来源）目前共用用人组织的页面权限及 CRUD 权限。仍有下属用人组织的来源不能删除，需先调整组织归属。删除来源会删除它的 ODC 配置。

## 发布

先应用 `apps/ai-recruitment-copilot/drizzle/20260908020000_add_resume_sources/migration.sql`，再发布应用。迁移只新增来源表、来源 ODC 关联表和用人组织的可空来源字段，不自动创建来源，也不迁移历史 ODC。

旧的部门／用人组织 ODC 记录保留，但不再参与授权。旧设置、单条增删改和批量设置接口返回 410；设置入口已隐藏。重新配置来源与 ODC 前，成员不会因历史 ODC 分配获得访问范围，其他招聘组或管理员权限照常生效。

## 从 Google 文档同步岗位

同步接受“部门/中心（来源）”“部门/中心”“简历来源”和“来源表格”表头，按此顺序优先读取，兼容旧表格。岗位同时保存部门/中心（来源） ID 和用于展示、筛选的来源文本。

按当前工作区逐级匹配：部门/中心（来源）名称 → 该来源下的编制组织名称 → 该组织下的部门名称。名称匹配会规范全半角、首尾及连续空格和字母大小写；命中已有节点时保留其原名称、描述和上级。不同来源下完全同名的用人组织及部门独立存在；同一层级内重复同步不会重复创建。已有未分配来源的同名组织也不会被搬到新来源。

来源为空时创建或复用“默认简历来源”；编制组织为空时在对应来源下创建或复用“默认用人组织”。部门为空的新岗位归入对应组织下的“默认部门”；已有岗位仅在父组织不变时保留本系统部门，否则归入新组织的默认部门，避免跨层级关联。

组织同步仅新增缺失节点，不修改或删除既有组织。岗位本身继续按唯一编码沿用原有更新和 Google 删除标记规则。同步结果会分别显示新增来源、用人组织和部门的数量。

## 招聘组负责范围

招聘组改为选择负责的部门/中心（来源）。岗位授权按岗位的部门/中心（来源） ID 判断，修改岗位来源后立即使用新的范围，不再从岗位旧部门或旧用人组织推导。组织、部门仍按来源层级可见，同时包含已授权岗位所属部门。不同来源下同名组织不共享岗位授权；原无来源公共岗位规则保留。

旧用人组织分配记录保留，但不迁移、不再授予访问权限。管理员需重新选择部门/中心（来源）。上线前应用 20260908040000_recruiting_group_resume_sources 数据库迁移。

## 岗位来源关联与历史回填

应用 `20260908130000_job_resume_source` 迁移后，岗位保存 `resumeSourceId`，以工作区与来源 ID 的复合外键防止跨工作区关联。迁移按当前工作区和规范化名称复用已有来源，缺失时创建；空来源保留为空，不搬动原有用人组织或部门，也不改写 ODC／招聘组配置。可重复执行。

岗位新建／编辑选择系统来源并提交 ID；新建来源成功后自动选中。来源改名同步更新关联岗位的显示文本，权限继续绑定原 ID；仍有关联岗位或用人组织的来源不能删除。Google 同步也写入该 ID。

ODC 简历可见性按关联岗位的来源以及配置中的序列、服务单位共同判断；撤销挂靠或取消 ODC 角色标记立即失效。普通 ODC 只能看到已经通过 AI 分析审批且在审批时明确指派给自己的候选人；待审批、审批未通过或未指派的简历不会因来源挂靠而暴露给 ODC。招聘组的岗位范围按其负责的来源判断，简历原有的创建人、汇报关系规则保留，但不能绕过这条 ODC 接收限制。

## 预录入 ODC 配置

预录入新建／编辑选择标记为 ODC 的工作区角色后，可选择“指定部门/中心”或“全部部门/中心（包含以后新增）”。指定模式可多选来源，并为每个来源设置序列和服务单位；这两项留空表示不限。配置仅接受当前工作区的来源，角色判断使用角色的 ODC 标记。

首次创建工作区成员时将范围模式和指定来源配置写入成员，招聘组为空也会生效。已有工作区成员的 ODC 范围以成员配置为准；预录入按当前邮箱显示实际范围及成员管理链接，不再允许从预录入修改。编辑预录入、重复应用或再次登录都不会覆盖已有成员的 ODC 范围。其他预录入字段沿用原来的同步行为；更换邮箱不会撤销旧账号的配置。

先应用 `20260908143000_pre_registration_odc` 迁移，再发布应用。迁移为预录入记录增加默认空数组的 ODC 配置。来源若在注册前已被删除，注册时跳过该来源，编辑预录入时需移除失效选项。

## 工作区成员的 ODC 负责范围

应用 `20260921170000_member_odc_scope` 迁移后，工作区成员及预录入记录增加 `odcScopeMode`，数据库默认值为 `selected`。现有来源挂靠保持不变。该字段属于工作区成员，不属于全局用户，也不通过通用用户资料接口修改。

该迁移兼容此前通过 `db push` 创建了字段和约束、但尚未登记迁移记录的数据库：保留定义匹配的对象及现有数据，补齐缺失对象。若已有字段类型、默认值、非空要求或同名 CHECK 约束与预期不符，迁移会报错并回滚，不会自动覆盖。部署数据库后续统一使用迁移流程，避免继续混用 `db push`。

管理员和拥有者在“成员与招聘组 → 成员 → 更多操作 → 设置 ODC 负责范围”中维护 ODC 成员的范围。成员表显示“全部部门/中心”或指定数量。`all` 动态覆盖当前工作区现有及以后新增的来源，不限序列和服务单位；不会生成每个来源的挂靠记录。切换到 `all` 保留原指定明细，切回 `selected` 时可恢复并调整；指定列表为空不授予 ODC 来源访问。取消 ODC 角色立即停止 ODC 授权，保留配置以便恢复角色后使用。

部门/中心侧的 ODC 展示、管理列表和审批指派候选包含全部范围 ODC，且不会与保留的指定明细重复计数。全部范围成员不能在单个来源下移除或修改限制，需前往成员管理调整；批量保存指定成员也会保留全部范围成员的备用明细。

全部范围只扩大来源覆盖，不授予管理员、审批或其他操作权限。普通 ODC 候选人可见性仍要求审批通过并明确指派，且保持工作区隔离。上线时先执行迁移，再发布后端和 Web；无需批量重建来源挂靠。

## AI 评价审核

候选人管理新增流程起点：AI 评价审核 → 简历筛选 → AI 面试 → 真人面试 → Offer → 已结束。

新建简历、批量上传到候选人管理，以及从公共／私有简历池加入的记录，均先进入 AI 评价审核。更换岗位会重置评价并返回审核阶段。历史候选人不批量回退；在审核阶段结束的候选人，重新激活时仍返回审核，不能跳过审批。

审批资格由工作区角色的 `aiReview:approve` 权限控制。有该权限的角色可审批当前工作区全部处于 AI 评价审核阶段的候选人，不受部门/中心（来源）、ODC 身份、序列或服务单位限制。管理员和拥有者默认拥有此权限。部门/中心（来源）中的旧审批勾选项已移除，历史数据库字段保留兼容，但不再作为授权依据。

关联岗位且 AI 评价生成完成后，有权限的成员可点击“审批通过，进入简历筛选”，填写审批说明。审批会记录操作人、说明和阶段变化。未批准时保留在审核阶段，不能跳过审批推进面试。

首次启用审核阶段仍需应用 `20260909100000_add_candidate_ai_review/migration.sql`。本次角色授权调整无需新增数据库迁移，也不会自动向已有 ODC 角色授予全工作区审批权限。

### AI 分析审批工作台

“招聘工作台 → AI 分析审批”以分页表格展示当前工作区所有处于 AI 评价审核阶段的候选人，支持姓名搜索、候选人概览和 AI 评价。审批成功后候选人移出待审列表。

在“角色与权限”中新建或编辑审批角色，配置：

1. 页面浏览 → AI 分析审批。
2. 招聘流程 → AI 分析审批 → 查看。
3. 招聘流程 → AI 分析审批 → 审批。

前两项控制页面及待审数据访问，第三项控制审批操作。无需额外开放候选人管理、AI 面试管理或 ODC 身份。具有审批权限的成员在候选人管理列表、统计和详情中，也能看到本工作区全部 AI 评价审核候选人，包括上级和其他招聘组的数据。该阶段范围与原有上下级、招聘组及 ODC 可见范围取并集；其他阶段和跨工作区隔离继续按原有规则处理。

### 管理员完整权限

工作区管理员和拥有者均从完整权限目录获得页面与资源权限，包含工作区删除。成员管理中可调整其他管理员和自己的角色；将现有成员设为拥有者会在事务内转移所有权，原拥有者变为管理员。最后一位拥有者不能直接被降级或移除，需要先转移所有权。

管理员可以管理本工作区其他成员的简历池记录，包括导入、发布、重新解析和删除。跨工作区隔离、候选人流程状态和审批说明必填等数据规则继续生效。平台级管理员是独立身份，不通过工作区角色授予。
