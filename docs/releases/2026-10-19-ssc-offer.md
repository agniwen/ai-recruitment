## SSC 负责组织数据导入

“SSC 负责组织”列表在“新增 SSC 负责组织”旁增加“数据导入”按钮。管理员可以下载模板、选择工作区内现有的 SSC 审核角色，上传表格后查看逐行预览，确认后整批导入。

| 项目 | 行为 |
| --- | --- |
| 文件格式 | Excel `.xlsx`、TSV `.tsv` |
| 文件限制 | 每次最多 500 行，文件不超过 5 MB |
| 导入字段 | 需求对接负责人、中心/部门、SSC 花名、SSC TG、SSC 邮箱、备注 |
| 表头兼容 | 兼容原表的 `SSC-花名`、`SSC-tg`、`SSC-邮箱`，忽略表头空格、连字符及大小写差异 |
| 不完整资料 | SSC 姓名、TG、邮箱等联系方式允许留空，保留预录入记录 |
| 部门/中心关联 | 当前工作区内唯一同名时自动关联；找不到时保留原名称并标记待关联；同名存在歧义时提示修正 |
| 重复关系 | 文件内及已保存的重复关系跳过，保留已有资料 |
| 错误处理 | 预览提示错误行；有错误或成员角色冲突时整批不写入 |

导入沿用 SSC 管理员与页面权限校验。预览只读；确认时重新校验角色、部门和负责关系，并核对预览结果。预览后发生匹配变化时，提示重新预览，避免保存未经核对的组织分配。

导入成功后刷新 SSC 负责关系、可选人员及工作区成员数据。邮箱匹配与角色同步沿用现有 SSC 维护规则，未注册人员继续保留预录入资料。

## Telegram Offer 确认

- Offer 卡片提供“接收确认”和“完成确认”，与系统使用同一套身份、负责范围、节点权限及版本校验。
- 状态依次为“待 SSC 接收 → 确认中 → 已完成 SSC 确认”；操作结果同步到系统和 TG 卡片。
- 点击“完成确认”后，先确认内部审批已完成；审批截图选填，上传截图本身不会完成确认。
- 审批确认按钮采用两行短文案，减少 Telegram 截断按钮文字的情况。
- 重复点击、过期会话、旧版本和失去权限后的操作均不能重复推进流程。

## 免登录候选人详情

TG 卡片的“查看候选人详情”打开独立只读页面，沿用系统候选人页面的“概览 / AI评分 / 真人复面 / Offer”四个页签。

- 概览展示 AI 综合评分、六维雷达图、评价摘要、候选人信息及活动记录。
- 顶部提供刷新和原始简历预览入口，可查看实际上传的简历文件。
- AI 评分和真人复面页签展示已保存的评价依据、面试轮次、评分与反馈。
- Offer 页签展示本次 Offer 的职位、薪资及 SSC 确认状态和时间。

链接使用签名并绑定工作区、候选人、Offer、收件人、修订号和有效期；读取时重新核对现有权限。公开页面采用明确字段投影及禁止缓存、禁止索引、禁止 Referer 传递等响应设置。

正式部署时，详情链接使用可从公网访问的应用 HTTPS 地址，外部收件人无需登录 ATS。工作区管理页面继续使用登录和权限校验。

## 发布与配置

- 本次没有新增数据库迁移或依赖。
- SSC 导入需要当前工作区已有 SSC 审核角色；维护入口沿用现有管理员和页面权限。
- TG 功能继续使用部署环境中的 Bot Token、Webhook Secret 和 Worker 配置；入站回调与发卡服务需要属于同一环境。
- Web/Backend 和发卡 Worker 使用一致的签名密钥及应用域名；正式发布后从正式系统生成详情链接。
- 截至本次验证，功能已部署于本地测试环境；正式环境待合并并发布。
