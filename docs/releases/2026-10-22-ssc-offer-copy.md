# SSC Telegram Offer 全文复制（2026-10-22）

SSC 收到的 Offer 通知新增完整确认文本及复制入口，内容复用系统的 Offer 模板，包括候选人编码、系统记录编码、编制和薪资。SSC 状态继续独立显示在卡片及系统进度中。

## 使用方式

- 普通长度的完整内容以 Telegram 普通文本展示，避免代码块背景随富文本粘贴带入目标软件。原生复制按钮直接复制文字，不打开链接。
- 通知、接收后的更新卡以及内部审批确认卡使用原生 `copy_text` 按钮。正文不超过 256 个 UTF-16 单元时显示“复制 Offer 信息”；更长时按完整行优先分段，显示“复制第 1/2 段”等。每段分别复制、粘贴，每次复制会覆盖剪贴板，不会自动追加。
- Telegram 卡片只保留“查看候选人详情”和原生复制按钮，不再提供单独的“打开全文复制页”链接。超长 Offer 可从候选人详情进入 Offer 页签复制全文。
- 详情页及系统 Offer 信息弹窗新增“复制 Offer 信息”按钮，复制全部文本和换行；不会触发创建、保存或 SSC 确认。
- 待确认时，Offer 文本不再附加“待 SSC 确认”尾行，并清除多余尾部空行；确认中及完成后的既有文本保留。已保存正文中相同的字样不会被误删。
- 原生 `copy_text` 每段不超过 256 个 UTF-16 单元，不拆开代理对，也不删除空白和换行；所有分段拼接必须精确还原原文。最多展示 8 段，超过时整组转为明确的网页全文复制提示，不提供残缺的部分正文。普通消息长度预算仍独立执行，避免消息正文被适配器截断。

## 数据与边界

- 通知从当前候选人最高 Offer 版本读取已保存的确认快照、薪资和币种，不用测试候选人或重新拼接其他版本的数据。
- 候选人详情链接保留原有版本、权限、有效期和 SSC 归属校验；公开只读数据增加当前已授权候选人的记录 ID。
- 旧版未保存确认快照的 Offer 可复制已有职位、薪资和候选人姓名；有快照时保留其中的空值，不覆盖为当前候选人资料。
- 复制成功、手动复制和失败分别提示；只在浏览器确认写入剪贴板后提示成功，并防止重复点击或误提交表单。HTTP 或剪贴板被拒绝时，使用只读多行弹窗保留全文与换行，可全选手动复制，不经过单行 prompt。
- 接收确认、完成确认、审批截图和操作记录继续使用既有流程。开发代码不启用本地自动发送；临时联调由私密操作目录中的独立回调与到期恢复进程管理。
- 原生键盘通过应用 Telegram adapter 的 `postMessage`、`editMessage` 和 SDK 支持的 protected 请求扩展注入，与原有正文、链接和审批回调在同一个 API 请求中发送；并发消息使用独立作用域，普通绑定或面试通知透传。没有修改 SDK 文件或全局 fetch。
- 无数据库迁移或依赖变更。

## 兼容性依据

- [Telegram CopyTextButton](https://core.telegram.org/bots/api#copytextbutton)：原生按钮支持 1–256 字符。
- [Telegram formatting options](https://core.telegram.org/bots/api#formatting-options)：正文中的 Markdown 标点以纯文本转义，避免已保存的反引号或多行内容产生代码格式。
- [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage)：普通消息正文长度受 4096 字符限制。
