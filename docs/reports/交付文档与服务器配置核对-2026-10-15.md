## 3. LiveKit Webhook 缺失的证据与影响

生效配置链已确认：

1. `.229` 的容器将宿主机 `/opt/livekit/livekit.yaml` 挂载到 `/etc/livekit.yaml`。
2. 启动参数是 `--config /etc/livekit.yaml`，未设置 `LIVEKIT_CONFIG` 等额外配置环境变量。
3. 文件修改时间早于当前容器启动时间，文件中没有业务 `webhook.urls`，也没有对应 `webhook.api_key`。
4. 当前应用签发 AI / 真人面试 Token 的 `RoomConfiguration` 没有另行设置房间 Webhook。

当前代码在 `POST /api/livekit/webhook` 处理以下事件：

| 事件 / 调用                              | 业务用途                      | 缺少 Webhook 时的缺口                                              |
| ---------------------------------------- | ----------------------------- | ------------------------------------------------------------------ |
| `room_started`、`room_finished`          | 更新真人面试会议开始/结束状态 | 这条服务器事件驱动的状态更新链路无法运行                           |
| `participant_joined`、`participant_left` | 更新参会记录与入离会时间      | 缺少由 LiveKit 提供的参会事件                                      |
| `saveLiveKitTelemetry`                   | 保存服务器侧诊断事件          | 诊断记录缺少该来源                                                 |
| `signalMediaRoom`                        | 触发真人面试采样/房间结束处理 | 已设置 `HUMAN_INTERVIEW_MEDIA_ENABLED=true` 仍不足以保证完整事件链 |
| `egress_ended`                           | 回写最终录像状态和时长        | Agent 自身上报之外的异步完成回写缺失                               |

建议在**实际音视频主机**的配置中补齐以下片段，并使用与应用匹配的现有 LiveKit Key；这是待实施的修改建议，本次未写入服务器：

```yaml
webhook:
  api_key: "<与应用匹配的现有 LIVEKIT_API_KEY>"
  urls:
    - "https://recruitment.hirecopilot.bar/api/livekit/webhook"
```

后续发布应安排在途面试的结束窗口，并以一次获授权的真实面试验证入离会、诊断事件和录像完成回写。此次没有创建房间、发送模拟 Webhook 或触发录制，不能把配置结论当作已复现的业务故障或已完成修复。

代码依据：[LiveKit Webhook 处理](../../apps/ai-recruitment-copilot-backend/src/server/routes/livekit/route.ts)、[真人面试 Token 配置](../../apps/ai-recruitment-copilot-backend/src/server/routes/studio/routes/interviews/utils/human-interview-livekit.ts)、[AI 面试 Token 配置](../../apps/ai-recruitment-copilot-backend/src/server/routes/interview/route.ts)。
